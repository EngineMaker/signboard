# DECISIONS

実装中に決めたことの記録。新しいものを下に追記する。

## D-001: TypeScript はビルドせず `--experimental-strip-types` で直接実行

**日付**: 2026-09-20 / **Step**: 1

Node v24（開発機・サーバーとも）が型注釈の除去をネイティブに扱えるため、tsc でのビルド工程を置かない。
`tsc --noEmit` は型チェック専用として残す。

- 利点: ビルド成果物とソースの二重管理がなくなり、デプロイが「git pull して再起動」で済む
- 代償: Node 22 未満では動かない。`engines` で >=22 を宣言済み
- 再検討の契機: デコレータなど型除去だけでは扱えない構文が必要になったとき

## D-002: `createApp()` でアプリ生成とサーバー起動を分離

**日付**: 2026-09-20 / **Step**: 1

`src/app.ts` がアプリを返し、`src/server.ts` がそれを listen する。
テストは `createApp().request(...)` でポートを開かずに検証でき、テストの並列実行でポート衝突が起きない。

## D-003: 会話ログの保存は後続タスクとして保留

**日付**: 2026-09-20 / **Step**: 1

本プロジェクトの設計プロセス（プロンプトのやり取り）を後から振り返れるよう保存したい、という要望。
アプリの機能ではなくリポジトリの資産として扱う。MVP（Step 9）完了後、または区切りの良いタイミングで着手する。

- 想定: `docs/journal/` に設計判断の経緯を残す、もしくはセッションログのエクスポートを置く
- 保留の理由: MVP の実装を優先するため。急ぎではないとの確認済み

## D-004: 時刻はすべて UNIX epoch ミリ秒の INTEGER

**日付**: 2026-09-20 / **Step**: 2

SQLite に日時型はない。文字列で持つと比較（期限切れ判定）とタイムゾーンで事故るため、
全テーブルで epoch ミリ秒の INTEGER に統一する。表示時のみアプリ側で JST に整形する。

## D-005: 削除は論理削除、監査ログはDBトリガーで追記専用を強制

**日付**: 2026-09-20 / **Step**: 2

SPEC §2.7 で「削除されたお知らせの本文も監査ログから追跡できること」が要件のため、
notices は `deleted_at` による論理削除とし行を物理削除しない。

監査ログの改竄防止はアプリ層の規律だけに頼らず、`audit_logs` に BEFORE UPDATE / BEFORE DELETE
トリガーを置いて DB レベルで拒否する。アプリのバグや手動操作でも消えない。

- 代償: 運用で本当にログを消す必要が出たらトリガーを一時的に外す手間がかかる。保持90日の要件からは許容

## D-006: settings は KVS 形式（1項目1行）

**日付**: 2026-09-20 / **Step**: 2

設定項目は数個で、追加のたびに ALTER TABLE したくない。key-value の1行1項目とし、
値は JSON テキストで保存してアプリ側で型付けする。

壊れた値・型違い・未知のキーは既定値に倒す。**設定が壊れても掲示板は動き続ける**のが狙い
（SPEC §2.4 のオフライン耐性と同じ思想）。

## D-007: 掲示板の読み取りクエリに部分索引を張る

**日付**: 2026-09-20 / **Step**: 2

掲示板は「今生きているお知らせ」を繰り返し引く。
`idx_notices_active` を `WHERE deleted_at IS NULL` の部分索引にし、削除済みを索引から外す。

## D-008: 掲示板画面はビルド工程なしの素の HTML/CSS/JS

**日付**: 2026-09-20 / **Step**: 3

対象が Safari 16 (iPad Pro 9.7 / A9X) 固定。バンドラを挟むと transpile ターゲットの調整が
必要になるうえ、壊れたときの原因追跡が増える。`public/` をそのまま配信する。

- アニメーションは `transform: translate3d` のみ。GPU 合成に乗せ、A9X でも滑らかに保つ
- `:has()` など Safari 17+ の機能は使わない
- 再描画は内容に変化があったときだけ。毎回 DOM を差し替えるとスクロールが先頭に戻ってしまう

## D-009: 表示設定の既定値を実測して調整

**日付**: 2026-09-20 / **Step**: 3

当初 fontScale 22（= 22vh）としたが、実際に描画すると 169px となり画面に2文字しか入らず、
文として読めなかった。12（約92px）に変更し、あわせて scrollSpeed を 120→220 px/秒に上げた
（文字が大きいほど一周に時間がかかるため）。

**教訓**: 表示系の既定値は机上で決めず描画して確認する。最終的な値は実機で詰める。

## D-010: Discord アプリのアイコンは生成スクリプトで管理

**日付**: 2026-09-20 / **Step**: 4（準備）

アイコンを画像編集ツールで作ると再現・微調整ができない。`assets/make-icon.py` でドットマトリクス
（琥珀色の LED 掲示板風、文字は "EM"）を生成し、SVG をリポジトリに置く。
色・文字・ドット密度はスクリプト上部の定数で変えられる。

    python3 assets/make-icon.py > assets/app-icon.svg

**検討した案**: 掲示板の絵（小さいと潰れて判別不能）、「掲」の一文字（明快だが電光掲示板らしさが薄い）。
Discord のサーバー一覧では 48px 程度で表示されるため、小サイズでの可読性を基準に選んだ。
